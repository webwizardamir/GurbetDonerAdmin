You Phase 1 — Point the ADMIN project at its new folder

⚠️ Do this first, right after Claude says the push is done. Fixes the "failed build" and gets the admin app green again.

  1. Open your existing admin project in Vercel
    It's the one serving melek-halal-food.vercel.app.
  2. Settings → Build & Deployment → Root Directory
    Set it to apps/admin and save.
  3. Deployments → … → Redeploy
    The build should now go green. Check melek-halal-food.vercel.app still loads & you can log in.
Env vars (VITE_SUPABASE_URL etc.) already live on this project — you do not need to re-add them.

You Phase 2 — Point the WEBSITE project at its new folder

Your Astro site already has a Vercel project. We just re-aim it at the new repo + folder (keeps its settings & env vars).

  1. Open your existing public-site project in Vercel
    The one currently building the Astro site from the old melek-halal-fontend repo.
  2. Settings → Git → Connected Git Repository
    Change it to webwizardamir/MelekHalalFood (this repo).
  3. Settings → Build & Deployment → Root Directory = apps/web
    Framework should auto-detect as Astro. Save.
  4. Redeploy & verify the site loads
Prefer a clean slate instead? You can create a new Vercel project, import MelekHalalFood, set Root Directory to apps/web — but then you must re-add any env vars the site uses. Re-aiming the existing project is easier.

You Phase 3 — Attach the domains in Vercel

Add the domain names to each project. Vercel will then hand you the exact DNS records for Phase 4.

  1. WEB project → Settings → Domains → Add
    Add melekhalalfood.nl and www.melekhalalfood.nl. Let Vercel set www → apex redirect.
  2. ADMIN project → Settings → Domains → Add
    Add app.melekhalalfood.nl.
  3. Copy the DNS values Vercel shows
    Each domain will show an A record or CNAME with a target value. Keep that screen open for Phase 4.

You Phase 4 — Add the DNS records at TransIP

In TransIP → your domain melekhalalfood.nl → DNS settings. Use whatever Vercel told you in Phase 3 — the table below is the typical Vercel values as a guide.

Name / HostTypeTypical Vercel valueFor
@ (root)A76.76.21.21melekhalalfood.nl → website
wwwCNAMEcname.vercel-dns.com.www → website
appCNAMEcname.vercel-dns.com.app → admin app
⚠️ Always use the exact value Vercel shows you — it occasionally differs. If TransIP already has a default A record on @ pointing elsewhere, replace it. DNS can take a few minutes to a couple hours; Vercel auto-issues the SSL certificate once it sees the records.

You Phase 5 — Tell Supabase about the new addresses

So portal logins, invite links and password resets work from the new domain. Supabase → Authentication → URL Configuration.

  1. Set Site URL
    https://app.melekhalalfood.nl
  2. Add these to Redirect URLs
    https://app.melekhalalfood.nl/**
    https://melek-halal-food.vercel.app/**
  3. Save
    Then test a portal login + a password-reset link on the new domain.
Keep the old .vercel.app entry — it lets you fall back to the Vercel URL if a DNS change ever hiccups.

You Phase 6 — Security actions before launch

From the 2026-06-29 pre-launch audit. The code/DB fixes are already done & deployed (migrations 00074/00075). These remaining items can only be done in the dashboards.

  1. 🔴 Rotate the Supabase API key (critical)
    A full-access service_role key was committed to git history. Supabase → Settings → API → rotate the JWT secret (or migrate to new API keys). ⚠️ This also changes the anon key, so right after: update VITE_SUPABASE_ANON_KEY in Vercel (admin project) and redeploy, or the live app breaks. Edge functions update automatically.
  2. 🟠 Enable leaked-password protection
    Supabase → Authentication → Policies → turn on the HaveIBeenPwned check (one toggle).
  3. 🟠 Lock the edge-function CORS origin
    Set function secret ALLOWED_ORIGIN = https://app.melekhalalfood.nl (functions default to *; the code already reads this var).
  4. 🟠 Confirm Auth min password length ≥ 8
    Supabase → Authentication → password policy.
